How it works

One Mac is the engine: every session runs there, and you can work at it directly. On its own it is the whole tool. Any other Mac can be a client: you work from it, and what it does, it does on the engine. Your code reaches the other machine through GitHub; a handover carries work in progress straight between them over SSH.

A session stays where it started

  • Sessions live on the engine, inside Zellij. Your terminal, the app, VS Code and your phone are only windows onto them.
  • Close any window and nothing stops. Join again from anywhere and it is where you left it; a dropped connection rejoins on its own.
  • Claude's conversation stays with the session, on the engine, whichever machine you joined from.
  • Your phone works too: with Remote Control on, every session is in the Claude app under its own name.

What you no longer do by hand

  • Find the right tmux or Zellij session
  • Keep a terminal open per piece of work
  • Work out each worktree's ports
  • Forward ports to test the app
  • Copy secrets between machines

Start new work

  1. {{.Site.Command}} new project-a fix-loginAsked on the laptop; planned and run on the engine, over SSH.
  2. git -C ~/src/project-a fetch originBring the remote's branches up to date.
  3. git -C ~/src/project-a worktree add -b fix-login ~/src/project-a-fix-login origin/mainA worktree beside the clone, on a new branch.
  4. {{.Site.Command}} slot claim --worktree ~/src/project-a-fix-loginIts own slot of ports, written into the worktree.
  5. {{.Site.Command}} secrets restore project-a --worktree ~/src/project-a-fix-loginThe project's secret files, from your settings.
  6. zellij attach --create-background project-a-fix-login …Its session, Claude Code in the first tab.
  7. {{.Site.Command}} join project-a-fix-loginJoined in a Ghostty tab on the laptop.

Run the app, use it on the laptop

  1. {{.Site.Command}} up project-a-fix-loginRun, from the app or from inside the session.
  2. upThe project's up script starts its servers on the slot's ports.
  3. ssh … -O forward -L 20110:localhost:20110 engine.exampleForwarded over one SSH connection, same numbers.
  4. http://localhost:20110/Sign-in callbacks and cookies work as if it ran here.
  5. code --remote ssh-remote+engine.example ~/src/project-a-fix-loginEdit the same files, on the engine.

Keep settings and secrets in step

  1. {{.Site.Command}} secrets save project-aCopies the files engineroom.toml names into secrets/.
  2. {{.Site.Command}} settings syncPushed encrypted: GitHub only ever holds encrypted bytes.
  3. {{.Site.Command}} settings syncThe laptop takes them; its own key decrypts them.
  4. {{.Site.Command}} secrets restore project-aInto a checkout that lacks them; never over a file it has.

Work local, then hand back

  1. {{.Site.Command}} offline onThe handover is shown first, one line per checkout, and checked in full: if anything would stop the laptop matching the engine, nothing runs and it says what to clear.
  2. git -C ~/src/project-a-fix-login push origin fix-loginThe work checked out is pushed; other branches are left as they are, and named.
  3. git -C ~/src/project-a-fix-login switch -C fix-login 3f2a9c1Each copy on the laptop takes the engine's branch and commit, its own changes set aside in its stash list; a missing project is cloned.
  4. {{.Site.Command}} handoff pack ~/src/project-a-fix-loginUncommitted work is stashed on the engine and carried straight over SSH, never through GitHub, then applied: the laptop is where the engine was.
  5. {{.Site.Command}} open project-aSessions now run on the laptop, and every screen says so.
  6. {{.Site.Command}} offline offHand back: the same handover, the other way.

Finish and clean up

  1. {{.Site.Command}} clean project-a fix-loginRefused while work would be lost, with ways to keep it.
  2. downThe project's down script stops its servers.
  3. {{.Site.Command}} session reap project-a-fix-loginThe session ends; anything still running for it stops.
  4. {{.Site.Command}} slot release --worktree ~/src/project-a-fix-loginThe slot is given back.
  5. git -C ~/src/project-a worktree remove ~/src/project-a-fix-loginThe worktree goes.
  6. git -C ~/src/project-a push origin --delete fix-loginThe branch goes, here and on GitHub, only if it is merged.

Every action is real commands

  • Read it before it runs. Each action is a plan of ordinary commands, each with its reason.
  • Watch it while it runs, and find it afterwards in the history, with its output.
  • Copy any of it. Copy all joins them with &&, so a paste stops at the first failure, as the program does.
  • Nothing changes unasked. A problem is reported with its fix, applied only when you ask.

Your app, on your laptop's own localhost

  • Every worktree has its own ports, so copies of one project run side by side on the engine.
  • Forward a worktree, or just open its link, and its ports answer on your laptop under the same numbers, over one SSH connection. A link whose app is not running starts it first.
  • Same numbers on localhost means nothing breaks: sign-in callbacks, cookies and allowed origins behave as if the app ran on the laptop.

When the engine does not answer

The engine did not answer.

Nothing has been started on either machine. Sessions already running on the engine keep running.

Retry the engineWork local on this Mac

  • Never a quiet fallback. The app says the engine did not answer, and what that means.
  • Work local takes the work over, committed and not, and hands it back later. Switching stops nothing.

Nothing left running behind you

What a session starts belongs to it. Stopping the session stops its servers, and a session that ends some other way has them stopped two minutes later. An editor you opened is never touched.
