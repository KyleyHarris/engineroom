Many sessions on one Mac, each on its own branch and ports, none in another's way. Work on them at that Mac, or from your laptop anywhere, with the app each one is building on your own localhost.

Install it See how it works

Every session, from the menu bar

The same list in the menu bar, in a window and in the terminal. One light per project, Claude's mark on the one that is waiting for you.

One Mac is enough. More is better.

The Mac that runs the sessions is the engine. It is the whole tool on its own; another Mac only adds a way in.

  1. The engine on its own

    Everything, on one Mac

    • Sessions that outlive the terminal, a waiting one marked
    • A worktree, branch and slot of ports for each piece of work
    • The app each session builds started and stopped with it
    • Settings and secrets kept in a repository of yours
    • Every action shown as the commands it runs

  2. At the engine

    Work on it directly

    • Its own menu bar, terminal and VS Code, on its own files
    • No SSH in between: every session is local
    • Walk away and the sessions keep going

  3. Anywhere else

    A laptop as a client

    • The same list, the same sessions, joined over SSH
    • The app on your laptop's localhost, VS Code on the engine's files
    • No engine to reach? Work local, and hand back later

With Remote Control on, every session also answers from your phone, however you use it.

Why {{.Site.Product}}

  • Close the terminal. The work goes on.

    Every session lives in Zellij on the engine. Close the window, or shut the laptop, and it is where you left it.

  • Six sessions. Which one needs you?

    One list in a fixed order. A session waiting for an answer is marked, with Claude's question.

  • Three copies of one app, one set of ports.

    New work gets its own worktree, branch and slot of ports, so copies run side by side without colliding.

  • The app is on the engine. You are on the laptop.

    Its ports answer on the laptop's own localhost, same numbers, so sign-in and cookies just work.

  • Settings and secrets on every machine.

    Kept in a private repository of yours, secret files encrypted, set up the same on every Mac.

  • No forgotten servers. No hidden steps.

    What a session starts stops with it. Every action is real commands you can read first and copy.

Install it

You need a Mac with Go, Zellij, git and Claude Code. The setup page lists every item, why it is needed and how to check it.

  1. Let Claude set it up

    In Claude Code, add the plugin, then ask Claude to set this machine up. It installs what is missing and changes nothing without asking.

    /plugin install {{.Site.Command}} --marketplace {{.Site.RepositoryPath}}

  2. Or install it by hand

    Builds the command into ~/.local/bin and the menu bar app into ~/Applications, printing every command it runs.

    git clone {{.Site.Repository}} && cd {{.Site.RepositoryName}}
scripts/install.sh --app

  3. Make this Mac the engine

    Register a repository, then open {{.Site.Product}} from the menu bar, or run it in a terminal for the same list.

    {{.Site.Command}} role set engine
{{.Site.Command}} project add ~/src/project-a
{{.Site.Command}}

A second Mac joins as a client with {{.Site.Command}} role set client --engine engine.example, naming the engine as an SSH destination.

Why not just Claude's Remote Control?

Keep it: {{.Site.Product}} can turn it on for every session. Remote Control is a window onto a session on one machine, and Anthropic's docs say that machine "has to stay on and the claude process has to keep running". {{.Site.Product}} is that machine, and everything around the session.
